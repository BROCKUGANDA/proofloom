    63→# PART II. PRODUCT VISION
    64→
    65→## 3. What PROOFLOOM is
    66→
    67→PROOFLOOM is a verifiable engineering and software provenance platform.
    68→
    69→It creates an evidence-backed record of how software is developed, modified, tested, released, verified and maintained, including work performed by autonomous AI agents.
    70→
    71→The platform connects:
    72→
    73→- Software repositories.
    74→- Engineering teams.
    75→- Organizations.
    76→- Software components and dependencies.
    77→- CI/CD systems.
    78→- Build and release pipelines.
    79→- Human contributors.
    80→- AI agents.
    81→- Tasks and engineering activities.
    82→- Security policies.
    83→- Evidence artifacts.
    84→- Cryptographic attestations.
    85→- Public verification.
    86→- Blockchain commitments.
    87→- External developer tools.
    88→
    89→Its purpose is to make engineering activity independently inspectable and verifiable.
    90→
    91→A company should be able to establish:
    92→
    93→- What software was released.
    94→- Which source revision produced it.
    95→- Which dependencies were involved.
    96→- Which tests and security checks were performed.
    97→- Which people and agents contributed.
    98→- What evidence supports each claim.
    99→- Whether the evidence has changed.
   100→- Whether an attestation remains valid.
   101→- Whether a release has been revoked or superseded.
   102→- Whether another organization can independently verify the result.
   103→
   104→PROOFLOOM should become an infrastructure layer for trustworthy software production.
   105→
   106→## 4. Product philosophy
   107→
   108→**The architecture of trust, made visible.**
   109→
   110→The product should make complex engineering evidence understandable without diluting its technical rigor.
   111→
   112→The platform must serve several distinct audiences:
   113→
   114→- Founders and executives evaluating software trust.
   115→- Engineering leaders overseeing releases.
   116→- Security and compliance teams examining evidence.
   117→- Developers integrating repositories and pipelines.
   118→- AI-agent operators supervising autonomous work.
   119→- Independent auditors verifying claims.
   120→- External developers building on PROOFLOOM's protocol.
   121→
   122→Do not create one generic dashboard for all these users. Design purposeful workspaces and information hierarchies around their actual jobs.
